# ADR-008: T2 改用契约仿真端点发真 HTTP，MSW 弃用

- **状态**: 已接受 (Accepted)
- **日期**: 2026-10-11
- **关联**: `01` §1 / §3、`tools/jev-mock/`、`400-build` §3.7（S6）

## 背景

[ADR-003](adr-003.md) 确立了 T2 的技术路线：Vitest + MSW 在 **HTTP 层拦截**，并明确否决了「直接 mock `fetch` 函数」，理由是那样会跳过退避与超时、使 T2 退化为「测试 mock 自身」。

`v0.1.1` 落地 T2 时，三件事让这条路线不再成立：

1. **`ERR-01` 无法用拦截层表达**。`ERR-01`（网络不可达）的验收物是**真实的传输层断连**。HTTP 拦截层返回的是构造好的 `Response`，拿不到「socket 被切断」这个事实——最多只能返回 `599` 加一个标记头说明「这里本该是断连」。用一个自述的标记去验证「断连的处理」，验证的其实是标记本身。
2. **会同时存在两套端点行为**。`ADR-007` 已把契约仿真端点定为本版验收环境（真 Jev 注册暂停，`03` §2.1 的可执行镜像落在 `tools/jev-mock/`）。若 T2 用 MSW 构造响应、真机验收打仿真端点，二者对同一份契约的理解可能不一致——**T2 全绿而真机失败**，正是契约测试最该避免的假绿。
3. **并发峰值只能从上游侧观测**。客户端无法证明自己并发发了几个请求（这与 v0.1.1 最终靠 mock 的 `/stats.inFlight.peak` 取证是同一件事）。拦截层存在于客户端进程内，给不出服务侧的计数。

## 决策

- **T2 对 `tools/jev-mock/` 发真 HTTP**，不再做HTTP 层拦截。
- **`tools/jev-mock/handler.mjs` 成为唯一端点实现**：平台无关，Node 入口（`local.mjs`，供 T2 与真机验收）与 Worker 入口（`worker.mjs`）共用，杜绝两端行为漂移。
- **MSW 移出 `devDependencies`**；`msw ^2.15` 不再是 T2 的实现手段。
- T1 的依赖注入策略（`ADR-002`）**不受影响**——T2 换端点不改变 T1「不碰网络」的定位。

## 原因

1. **传输层真实性优先于响应构造**。`ERR-01` 是本版失败面的第一条，只能靠真实断连验证。Node 入口直接 `destroy()` socket，客户端 `fetch` 抛 `TypeError`，归一为 `ERR-01`——整条链路无一处模拟。
2. **单一端点实现消除假绿**。T2 与真机验收打的是同一个 handler，行为不可能漂移。这是 `ADR-007`「契约仿真端点验收」的题中之义：仿真端点必须同时服务于「测」与「验」，否则它只验了一半。
3. **上游侧可观测量真实可得**。重试次数（`byFault.rate429 = 块数 × 2`）与并发峰值（`inFlight.peak ≤ 4 且 > 1`）只能从服务侧读。拦截层方案下这些断言写不出来。
4. **规避 ADR-003 自己预警的风险**。该 ADR §35 已写明「MSW 在 Node 环境需显式 setup / teardown（可能替换全局 `fetch`），须确认用例间隔离，避免串扰」。真 HTTP 端点没有这个问题。
5. **代价可接受**。T2 从毫秒级升到约 1.8s（12 例），相对 S6 的门禁开销仍属噪声级。

## 后果

✅ `ERR-01` 用真断连验证，`disconnect` 故障在 T2 与真机验收中行为一致
✅ T2 与真机验收共用同一 handler，契约理解不可能分叉
✅ 重试次数、并发峰值、端到端预算三项断言成为可能——V0.1.1 S6 已据此补齐
✅ mock 与被测客户端同机，`localhost` 回环即可，无需外部依赖
⚠️ T2 需自行管理 mock 实例生命周期（测试内起停专用实例，与 T1 / 真机验收的实例隔离以免计数串扰）
⚠️ T2 耗时约 1.8s，不再是「毫秒级」；作提交前门禁仍可接受
🔧 `msw ^2.15` 从 `extension/package.json` 的 `devDependencies` 移除——本项目从未 `import` 过它，此前是**未使用的直接声明**。注意它作为 `vitest` 的**传递依赖**（`vitest` → `@vitest/mocker` → `msw`）仍留在依赖树中，属正常，不构成复用
🔧 回填 `01` §1 测试框架行与 §3 T2 运行方式
🔧 本 ADR 取代 [ADR-003](adr-003.md) 中「网络层拦截 = MSW」这一条；ADR-003 的其余结论（T1 依赖注入、不选 `@vscode/test-electron`、不 mock `fetch`）继续有效

## 替代方案

| 方案 | 否决原因 |
|---|---|
| MSW + 用标记头模拟断连 | `ERR-01` 退化为「验证自己写的标记」，传输层真相仍缺失；ADR-003 担心的「退化为测试 mock 自身」以另一种形式复现 |
| MSW（部分故障）+ 真端点（部分故障） | 两套端点行为并存，正是本 ADR 要消除的假绿来源；且需维护两份故障语义映射 |
| `nock` | 拦截 Node `http` 模块，对原生 `fetch` 需额外适配——ADR-003 已否决 |
| 直接 mock `fetch` 函数 | ADR-003 已否决：跳过退避与超时逻辑 |
| 继续 MSW 并接受「`ERR-01` 用 599 + 标记头近似」 | 本版失败面里 `ERR-01` 是`timeout` / `ERR-03` / `ERR-04` / `ERR-05` 之外唯一的传输层故障，不该是唯一被近似的一条 |
